薪資系統優化建議

1

薪資與加班費計算異常

破月計算導致時薪失真

目前常因員工「新報到、留職停薪、復職、離退」等未滿整月的狀況（破月），導致系統抓取的時薪發生錯誤（例如呈現 0 元或金額過高）。

基礎時薪的計算失誤，連帶造成後續的加班費給付計算錯誤，增加人事與出納作業負擔及員工爭議。

衍生計算與統一標準缺失

針對「破月」時的分母基數（如：是否固定除以 240 小時）以及跨職務轉換（如契約轉公職、行政轉助理等）的薪資比例計算，目前缺乏統一的標準公式。

系統自動化缺乏穩定的基礎規則，導致特例狀況必須倚賴大量人工計算與校正。

2

解決方案：新建薪資 Table

建置獨立資料表

建議建立一個全新的薪資 Table 機制，將底薪與各項加給資料模組化，作為跨單位系統取用薪資數據的唯一標準來源，根絕抓取錯誤。

定期資料匯入

由人事室與績效組定期將資料（如本俸、專業加給、夜班費等）匯入並維護。透過前端主動更新，確保系統隨時呈現正確、即時的時薪基礎。

解決特殊公式

此統一化機制可同步解決如「醫師免稅」等特殊群體的計算問題（總薪資除以240小時等特殊邏輯，實際公式依衛福部公告直接套入系統）。

3

跨單位協調與權責劃分

  • 資訊室： 資訊室同意協助建置新 Table 機制，確保系統架構足以支撐新的薪資運算邏輯。
  • 主動維護資料： 各單位（人事、績效、出納）必須在人員發生異動時「主動」維護資料表。
  • 主動回溯： 改變以往「等員工請領加班費失敗後，才被動回溯處理」的舊有流程，落實源頭管理。
  • 凝聚共識： 各單位須針對破月分母與跨職務轉換的比例計算，盡速召開會議確立統一標準。
4

管理流程優化：異動生效日規範化

  • 律定統一生效日 為了便於系統管理與薪資結算，建議人事室訂定規範：未來的職務異動、轉正等生效日，應統一律定於特定日期（如每月的 1 號或 16 號）。
  • 減少零碎破月 透過強制規範生效日期，能大幅降低破月天數過於零碎的狀況，讓薪資計算與系統運算邏輯大幅簡化，降低出錯率。
  • 專案特例處理 對於不可控的突發離職（如前一天才提離職等），則列為專案特例由人工介入處理，不影響通案的系統自動化邏輯設計。
